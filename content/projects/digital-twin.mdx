## The Problem

CNC machining operations rely on operator experience and scheduled tool changes to manage tool wear — a reactive approach that leads to scrapped parts, unplanned downtime, and wasted tooling budget. Acoustic emission (AE) sensors can detect the subtle ultrasonic signatures of tool wear in real time, but processing that signal data requires either expensive proprietary systems or a tethered laptop sitting next to the machine. For a university research lab running a HAAS CNC, neither option is practical.

The challenge was clear: build a wireless, low-cost monitoring system that could classify machining states at the edge — no cloud, no cables, no expensive DAQ hardware — and stream results to a browser dashboard in real time.

## What I Built

A complete edge-inference pipeline that captures acoustic emission data on an Arduino Nano 33 BLE, runs a 12-class CNN classifier on-device, and wirelessly streams predictions through an ESP32 bridge to a live browser dashboard. The entire system runs on battery power and fits in your hand.

### Signal Processing Pipeline

Raw AE sensor data is captured at high frequency on the Nano 33 BLE, where an FFT converts time-domain signals into frequency-domain features suitable for classification. The INT8 quantized TFLite Micro model runs inference directly on the Nano's Cortex-M4 processor, classifying machining states (idle, cutting, tool wear stages, chatter, etc.) without any cloud dependency. I built the training pipeline in Python using TensorFlow, with representative dataset quantization to minimize accuracy loss during INT8 conversion.

### Wireless Architecture

The Nano 33 BLE transmits classification results and confidence scores over Bluetooth Low Energy to an ESP32-WROOM-32, which acts as a WiFi bridge. The ESP32 hosts a lightweight web server that pushes data to any browser on the local network via WebSocket. This three-hop architecture — Nano → BLE → ESP32 → WiFi → Browser — was validated as a working proof of concept, with the full pipeline running end-to-end.

### Edge Deployment

The CNN model was trained on 12 machining state classes and deployed using TFLite Micro's interpreter on the Nano 33 BLE. Model size after quantization fits comfortably in the Nano's flash, leaving room for the FFT and BLE stack. There's a known confidence calibration bug — values occasionally exceed 1000% on the browser dashboard — likely caused by a dequantization or BLE parsing issue that's next on the fix list. AE sensors are on order to move from synthetic/accelerometer data to real acoustic emission capture.

## Tech Stack

Arduino Nano 33 BLE Rev2 (Cortex-M4), ESP32-WROOM-32, TensorFlow + TFLite Micro, Python ML pipeline (FFT, training, quantization), C++ Arduino sketches (9 iterations), BLE + WiFi protocols, browser dashboard with WebSocket. Academic research under Dr. Shendokar at Texas State University.
